☁️ Tus datos te siguen. Se guardan en este teléfono y también en tu propia nube. Si cambias de celular, entras con tu correo y está todo. No hay contraseña que recordar: te mandamos un código de 6 números cada vez.

Ojo con esto: quien pueda abrir tu correo puede entrar a tus cuentas. Cuida ese correo como cuidas el banco.

Para ser exactos: los datos viajan por internet a tu proyecto y solo se abren desde tu cuenta. No es cifrado de punta a punta, así que quien administre ese proyecto —o sea, tú— puede verlos.

Conectar tu nube

Hoy tus datos viven solo en este teléfono. Si conectas una nube, te siguen a cualquier dispositivo y no se pierden si pierdes el celular.

Te falta el paso del SQL. Copia esto, pégalo en Supabase en SQL Editor → New query, toca Run, y vuelve acá. Tiene que decir Success. No rows returned. 

create table public.estados (
  usuario_id      uuid primary key references auth.users on delete cascade,
  datos           jsonb not null,
  version_esquema int not null default 2,
  actualizado     timestamptz not null default now()
);

alter table public.estados enable row level security;

create policy "cada quien lee lo suyo"
  on public.estados for select
  using (auth.uid() = usuario_id);

create policy "cada quien crea lo suyo"
  on public.estados for insert
  with check (auth.uid() = usuario_id);

create policy "cada quien actualiza lo suyo"
  on public.estados for update
  using (auth.uid() = usuario_id)
  with check (auth.uid() = usuario_id);

Las tres reglas del final son lo que impide que otra persona lea tus gastos. No las borres.

Los dos datos salen de tu proyecto en Supabase, en Project Settings → API. Los pasos completos están en el archivo SUPABASE.md del proyecto. Antes de conectar revisamos que la dirección responda y que la tabla exista.

Ojo: la llave que va acá es la que dice anon public. Nunca la que dice service_role.
